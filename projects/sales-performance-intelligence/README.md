# Sales Performance Intelligence

**Project type:** Business Intelligence / Sales Analytics  
**Status:** Expanded portfolio release  
**Data:** 1,200 synthetic order lines across 24 months (fictional; generated for demonstration)

## Business scenario

A fictional multi-region retailer wants a clearer view of sales performance, profitability, product mix, and customer segments. This project establishes a reproducible analysis workflow that turns transaction-level records into management-ready metrics.

> **Data notice:** Every transaction in this project is synthetic. The dataset does not represent a real company, customer, employee, or commercial result. Seasonal patterns are generated by design and are not market evidence.

## Business questions

1. What are total revenue, cost, profit, profit margin, and average order value?
2. How do revenue and profit change month by month over two years?
3. Which regions and product categories contribute most to revenue and profit?
4. Which products generate the strongest and weakest profit?
5. How do customer segments compare by revenue, profit, and order volume?

## Run the analysis

From the repository root:

```bash
python -m pip install -r requirements.txt
python python/analyze_sales.py
```

The script validates the source data, prints executive KPIs and grouped summaries, and exports six reusable CSV tables to `outputs/`.

To regenerate the dataset deterministically:

```bash
python python/generate_sales_data.py
python python/analyze_sales.py
```

The generator uses a fixed seed and creates 50 single-line orders per month for January 2024 through December 2025. Each row represents one order line and one distinct order. It includes controlled product, region, sales-representative, segment, quantity, price, and cost variation. The generated November/December multiplier is a simulation assumption—not a real-world seasonal finding.

## SQL environment

The SQL file is written for SQLite. Import `datasets/sales_data.csv` into a table named `sales_data`, then run [sales_analysis.sql](../../sql/sales_analysis.sql). The grouped summaries use the same measures and revenue-first ordering as the Python reports.

## Automated validation

Run the unit tests from the repository root:

```bash
python -m unittest discover -s tests -v
```

GitHub Actions runs the tests and executes the analysis script on pushes and pull requests to `main`. The earlier 24-row release passed all eight tests and the analysis run in CI. The expanded dataset has been committed; its latest workflow run should be checked before treating the new release as fully validated.

## Scope and limitations

This is a portfolio demonstration built from synthetic data. Each order currently contains one line item, so basket analysis and multi-product order behavior are not modeled. Taxes, discounts, shipping, returns, refunds, operating expenses, inventory, and real customer identifiers are absent. The currency is unspecified. Do not interpret the generated patterns as real commercial performance or forecast evidence.

The Excel workbook binary is not yet committed; its companion documentation describes the planned workbook structure and validation status.
